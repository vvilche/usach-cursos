Agente lector de documentos

Sacar cifras de un balance sin leerlo a mano, y sin que la IA invente números.

La pregunta

¿Cómo sacas las cifras de un PDF sin leerlo a mano?

Un auditor recibe balances en PDF todo el día. Si el agente tiene que «leerlos como persona», no ganaste nada. La clave es la extracción determinista.

Concepto

Extracción determinista

Leer el texto del PDF con una librería (PyMuPDF), no pedirle al LLM que «recuerde» las cifras. El LLM formatea lo que el parser ya leyó: nunca inventa números.

Determinista = mismo PDF, misma salida, siempre. Sin aleatoriedad ni alucinación de cifras.

Por qué no el LLM

LLM leyendo vs. parser

LLM «leyendo» el PDF
  • Puede inventar montos que no están
  • Resultado distinto cada vez
  • No cuadra el balance
Parser (PyMuPDF)
  • Lee el texto exacto del PDF
  • Siempre la misma salida
  • Las cifras cuadran contra el original
Ejemplo

Balance → tabla

De un balance real, extraer las cuentas principales:
  1. Abrir el PDF y extraer todo el texto.
  2. Ubicar activos, pasivos y patrimonio.
  3. Emitir una tabla estructurada (cuenta, monto).
  4. Verificar: activo = pasivo + patrimonio.

La verificación del cuarto paso es la prueba de que la extracción fue correcta.

La tarea

Manos a la obra

Lee el PDF: usa PyMuPDF para extraer el texto plano.

Ubica las cuentas con regex o búsqueda de etiquetas («Total activos», etc.).

Entrega una tabla y que el agente la presente formateada.

El testeo

Que cuadre

La tabla extraída debe cuadrar contra el PDF: activo = pasivo + patrimonio.

Si no cuadra, es error de extracción, no del PDF. Ese es el estándar mínimo de un agente lector.
