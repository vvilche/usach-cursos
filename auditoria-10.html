Guardrails: Zod + Graft

Blindar el agente con validación de datos y mapeo del código del ERP.

La pregunta

¿Cómo haces que el agente RECHAZE un dato malo?

Un agente sin validación deja pasar basura. Con un schema, cada dato se chequea contra reglas antes de aceptarse.

Concepto

Guardrails de datos

Un schema (Zod/Pydantic) define qué es una factura válida: campos, tipos y reglas. Si un dato no cumple, el agente lo rechaza en vez de pasarlo.

Es el cinturón de seguridad: no evita que el modelo se equivoque, evita que el error llegue al reporte.

Dos herramientas

Zod + Graft

🔒 Zod

Valida datos: «el monto es número > 0», «el RUT tiene 9 dígitos». Rechaza lo que no cuadra.

🗺️ Graft

Mapea el código del ERP en un grafo legible para que el agente no se pierda entre módulos.

⚙️ Resultado

El agente valida cada transacción antes de aceptarla.

El efecto

Sin guardrails vs. con guardrails

Sin validación
  • Pasa un monto negativo o un RUT roto
  • El error llega al informe final
  • Nadie sabe dónde se rompió
Con schema Zod
  • Rechaza la transacción al instante
  • Cada rechazo dice qué regla falló
  • El reporte solo lleva datos válidos
La tarea (paso a paso)

Blindá tu agente

Definí el schema Zod: escribe qué es una factura VÁLIDA: qué campos tiene (RUT, monto, fecha), de qué tipo es cada uno y qué reglas debe cumplir (monto > 0, RUT con dígito verificador).

Mapeá el mini-ERP: con Graft, dibujá cómo se conectan los módulos (factura → pago → conciliación) para que el agente no se pierda.

Conectá la validación: que el agente chequee cada transacción contra el schema ANTES de aceptarla. Si falla, la rechaza y dice por qué.

El testeo

Que rechace

El agente rechaza una transacción que no cuadra y explica qué regla del schema la frenó.
